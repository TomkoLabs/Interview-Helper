# Project instructions

Read PROJECT_SPEC.md and PROGRESS.md first. Keep code and examples portable;
private infrastructure evidence and credentials never belong in Git. Use the
repository-local virtual environment. Preserve transcripts and local config.
Use feature branches and merge requests for changes. Never force-push or bypass
GitLab protection/review requirements. User-authorized integration may proceed
when the server permits it and no mandatory human review applies.

Before commits run relevant tests, inspect staged diffs, and push coherent
checkpoints. Initial incomplete checkpoints must be described as such.
Documentation completion is governed by the ancestor workspace AGENTS.md;
consult the workspace DOCS index/reference for infrastructure-facing changes.
